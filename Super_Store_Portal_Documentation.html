1. Executive Summary

The Super Store Portal is a comprehensive, full-stack Enterprise Resource Planning (ERP) and Point-of-Sale (POS) web application designed for retail store management. The system provides an integrated solution for inventory tracking, sales processing, supplier management, financial reporting, and online self-checkout capabilities.

Built with a modern JavaScript stack comprising React 19 on the frontend and Express 5 with MongoDB on the backend, the portal features role-based access control (Admin/Cashier), real-time dashboard metrics, Stripe-powered payment processing, Cloudinary-hosted product images, and Vercel serverless deployment support.

2. Project Overview & Objectives

2.1 Problem Statement

Modern retail stores require a unified platform to manage products, process sales, track inventory levels, manage supplier relationships, and generate financial reports — all from a single, cohesive interface. Traditional ERP systems are often expensive, overly complex, and difficult to customize for smaller operations.

2.2 Solution

The Super Store Portal addresses these challenges by providing:

  • Role-Based Access Control — Separate views and permissions for Admin and Cashier roles
  • Full POS System — Product search, cart management, customer selection, and real-time payment processing
  • Self-Checkout Integration — Customer-facing cart submission with Stripe payment processing via a separate store app
  • Inventory Management — Stock tracking, low-stock alerts, manual adjustments, and full stock movement audit trails
  • Supplier Traceability — Full traceability of products to their suppliers with inventory stats per supplier
  • Financial Dashboard — Real-time metrics including total sales, COGS, net profit, income, and expenses
  • Cloud Deployment — Vercel-ready serverless architecture with Cloudinary for image hosting

4. System Architecture

The Super Store Portal follows a monorepo, client-server architecture with a React SPA frontend communicating with a Node.js/Express REST API backend, backed by MongoDB Atlas.

4.1 Architecture Patterns

  • MVC Pattern — Models (Mongoose schemas), Controllers (business logic), Routes (endpoint definitions)
  • Service Layer — Complex business logic abstracted into service modules (e.g., supplierService.js)
  • Middleware Chain — Auth protection, role-based access, and file upload via composable middleware
  • Context API — React Context for global auth state management
  • Axios Interceptors — Automatic JWT injection and global 401 error handling
  • Serverless Adapter — Vercel-compatible api/index.js wrapping Express for serverless deployment

4.2 Data Flow

  1. User authenticates via /api/auth/login and receives a JWT token
  2. Token is stored in localStorage and attached to every subsequent API call via Axios interceptors
  3. Backend middleware validates JWT and checks user role before granting access
  4. Controllers process the request, interact with MongoDB models, and return JSON responses
  5. Frontend updates React state and re-renders components accordingly

8. Authentication & Authorization

8.1 Authentication Flow

  1. User submits email/password via POST /api/auth/login
  2. Server validates credentials against bcrypt-hashed passwords in the User collection
  3. On success, a JWT token is generated containing { id, role } with configurable expiry (default: 1 day)
  4. Token is stored in localStorage on the client
  5. Axios request interceptor automatically adds Authorization: Bearer <token> to every API call
  6. On 401 response, Axios response interceptor clears auth data and dispatches an auth-error event

10. Point-of-Sale (POS) System

10.1 POS Layout

  • Left Column (65%) — Product search grid (top) and current cart items (bottom)
  • Right Column (35%) — Toggleable panel: Active Cart / Pending Carts
  • Bottom Bar — Fixed bar showing subtotal and "Pay Now" button

10.2 POS Workflow

  1. Cashier searches products by name in the search grid
  2. Clicking a product adds it to the cart (or increments quantity)
  3. Cart displays items with +/- quantity controls and remove buttons
  4. Cashier selects or creates a customer (required before checkout)
  5. Clicking "Pay Now" validates cart items against current stock via POST /api/sales/validate
  6. Payment modal opens with payment options
  7. On success, sale is created, stock is deducted, stock movements are recorded
  8. Receipt is generated with invoice number

11. Self-Checkout & Cart System

The portal integrates with a separate customer-facing store application. Cart lifecycle: Draft → Submitted (30-min TTL) → Finalized (Sale + Stripe PaymentIntent created) or Cancelled.

Error Handling If Stripe PaymentIntent creation fails after the Sale is created, the system performs cleanup: Sale is deleted, cart is cancelled.

12. Stripe Payment Integration

Stripe is integrated server-side with amounts in PKR (Pakistani Rupee). The Payment model supports both POS-style (CASH/CARD) and online (STRIPE) payments with fields for stripePaymentIntentId, stripeClientSecret, webhookEventId, and cross-app compatibility via strict: false.

13. Inventory Management

Features

  • Stock Overview — View all products with current stock levels
  • Low Stock Alerts — Products where stockQuantity ≤ minimumStock
  • Stock Adjustment — Add or subtract stock with mandatory reason recording
  • Movement History — Full audit trail (SALE, PURCHASE, ADJUSTMENT, RETURN)

Each movement records previousStock, newStock, quantity, reason, createdBy, and reference to the triggering document.

14. Supplier Traceability

The supplier module implements a traceability system linking every product to its supplier with real-time inventory statistics:

  • Product count, total stock, inventory cost value, inventory retail value per supplier
  • Potential profit computation (retailValue - costValue)
  • Low stock count per supplier
  • Deletion protection — Cannot delete a supplier with linked products
